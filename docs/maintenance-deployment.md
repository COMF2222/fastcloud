# Публикация подготовленных изменений

Клиент подготовлен как **0.4.1**. Тег `v0.4.0` уже существует; его не нужно
перемещать или создавать повторно. Версии манифестов и lock-файлов согласованы.
`latest.json` с действительными ссылками и подписями создаёт релизный CI.
Админские функции не включены в публичные заметки этого выпуска.

## Что реализовано

| Бэкенд | Где проверять |
| --- | --- |
| Закрытая панель состояния: задержки, ошибки, нагрузка, диск, кеш | Управление пользователями → Здоровье сервера |
| Сохраняемый месячный бюджет трафика с предупреждением | Там же; 0 выключает бюджет, превышение не обрывает музыку |
| Приоритет популярного аудио и защита активного воспроизведения | Автоматически в серверном кеше |
| Объединение одинаковых запросов обложек и публичных метаданных | Автоматически; данные разных аккаунтов изолированы |
| Ограниченные повторы временно неудачных чтений | Один повтор, ограниченный срок; записи и загрузки не повторяются |
| Отдельные лимиты воспроизведения, поиска, метаданных и тяжёлых операций | Бэкенд сохраняет свободные места для аудио |
| Автоматические согласованные копии SQLite и проверка восстановления | Отдельный том `/backups`, интервал 1–24 часа |
| Проверка конфигурации и пробных миграций перед обновлением | `preflight.py` и `deploy_checked.sh` |
| Локальные сценарии 10–50 слушателей | `load_check.py`; результаты в `LOAD-RESULTS.md` |
| Объединение обновления токенов и правильное различение ошибок входа | Автоматически; отдельные тесты временной ошибки и `invalid_grant` |

| Сайт | Где проверять |
| --- | --- |
| Короткое описание пользы приложения | Первый экран |
| Галерея настоящих скриншотов | Главная → Внутри приложения |
| Понятный выбор полного установщика | Установка |
| Иллюстрированный первый запуск | Установка → Открой свою библиотеку |
| FAQ по пустой библиотеке, фрагментам, текстам и входу | `/faq` |
| Поиск в загруженной истории изменений | `/changes` |
| Публичный статус и сообщения о неполадках | `/status` |
| Полезные страницы о SoundCloud для Windows и текстах песен | `/soundcloud-windows`, `/lyrics` |
| Изображение для предпросмотра ссылок | OG/Twitter metadata всех страниц |
| Черновики ошибок/идей и поддержка проекта | `/feedback`; отправку подтверждает сам пользователь на GitHub |

Все страницы доступны на русском и английском. Приватная панель требует
проверки владельца на сервере. На публичном статусе нет пользователей, их
расхода API, трафика, диска или токенов.

## 1. Бэкенд

На компьютере, в PowerShell:

```powershell
cd D:\projects\fastcloud-backend
git add .github .gitattributes Dockerfile compose.yaml compose.ip.yaml server.py media.py relay.py upstream.py concurrency.py operations.py backup.py preflight.py load_check.py deploy_checked.sh OPERATIONS.md LOAD-RESULTS.md test_operations.py test_server.py test_relay.py test_media.py
git commit -m "feat: improve backend reliability and operations"
git push origin main
```

На сервере:

```bash
cd ~/fastcloud-backend
git pull --ff-only origin main
bash deploy_checked.sh -f compose.ip.yaml -f compose.vpn.yaml
```

Скрипт проверит конфигурацию и миграции на копиях, создаст точку восстановления,
перезапустит только бэкенд и проверит статус. Если используется сайт через
nginx-оверлей из соседнего репозитория, добавь к его аргументам
`-f ../fastcloud-website/deploy/compose.website.yaml`.

Убедись, что скрипт завершился с `Backend health verified`. Страница статуса
сайта требует этой версии бэкенда: только публичные `/health` и `/v1/status`
разрешают чтение браузером без учётных данных.

## 2. Сайт

```powershell
cd D:\projects\fastcloud-website
npm run build
git add public tools deploy README.md wrangler.jsonc
git commit -m "feat: add gallery status release search and feedback"
git push origin main
```

Дальше используй уже настроенную публикацию Cloudflare из GitHub. При ручной
загрузке публикуется весь каталог `public`, включая новые картинки и английские
страницы. Сайт остаётся статическим: отдельного Worker и нового секрета нет.
Файл `seo-audit-homepage.md` в команду добавления не включён.

После публикации проверь `/status`, `/en/status`, `/changes`, `/feedback` и
страницы Windows/текстов. Отсутствие свежих данных обозначается явно; это не
выдуманный процент доступности. История релизов подхватит 0.4.1 после публикации
клиентского релиза.

## 3. Клиент 0.4.1

Всплывающие панели (таймер сна, звук/эквалайзер, очередь, меню и палитра цвета)
получили отдельную непрозрачную подложку. Прозрачность основных панелей на неё
не влияет; цвет соответствует выбранной светлой/тёмной и пользовательской теме.

```powershell
cd D:\projects\fastcloud
git add .
git commit -m "feat: support updated backend operations"
git push origin main
git tag -a v0.4.1 -m "Fastcloud v0.4.1"
git push origin v0.4.1
```

Не продолжай к тегу, если commit/push завершились ошибкой. Сборку установщика
выполнит GitHub CI. Самостоятельная сборка или установка агентом не выполнялась.

## Проверки и границы результатов

Бэкенд: 66 тестов, проверки YAML и синтаксиса deploy-скрипта, локальные HTTP
сценарии 10 и 50 слушателей. Клиент: TypeScript, Cargo check всех targets,
17 фронтенд-тестов и 15 тестов релизных инструментов. Сайт: production build,
10 тестов, ссылки/ресурсы/переводы 19 HTML-страниц и проверка браузером.

Нагрузочный стенд использует настоящий HTTP-обработчик и аудиокеш, но ответы
SoundCloud и аудиобайты тестовые. Он не доказывает пропускную способность VPS
или качество декодирования настоящих записей. Трафик приложения не равен
счётчику провайдера: TLS/VPN/другие процессы не учитываются.

Копии на том же VPS не защищают от потери VPS. Команды экспорта на свой
компьютер и безопасной проверки восстановления находятся в `OPERATIONS.md`
репозитория бэкенда. Внешнее хранилище и расписание внешнего экспорта не
настраивались, поскольку места хранения ещё нет.
