# Обновления клиента и CLAP

Исполняемый файл Tauri включает Rust-код и интерфейс, поэтому обновляется целиком
через стандартный подписанный NSIS-установщик. Тяжёлые файлы CLAP обновляются
отдельно: неизменившиеся файлы не скачиваются, изменившиеся скачиваются по одному.
Это обновления на уровне файлов, а не бинарные патчи внутри `fastcloud.exe`.

## Переход со старых клиентов

- `latest.json` указывает на полный `Fastcloud_<version>_x64-setup.exe`.
  Он остаётся доступным для первых установок и клиентов со старым механизмом.
- Новые клиенты используют `latest-light.json`, который указывает на подписанный
  `Fastcloud_<version>_x64-update.exe` без CLAP.
- После первого полного перехода клиент проверяет и копирует готовые ресурсы
  из установочного каталога в собственное хранилище. Повторно скачивать их не нужно.
- Если установлен только лёгкий клиент, ресурсы готовятся в фоне. Проигрывание
  музыки работает во время подготовки, статус и повтор доступны в настройках
  обновления. Подключение к аккаунту не требуется для загрузки ресурсов.

## Формат и доверие

`tools/prepare_components.py` создаёт gzip-файлы `clap-<SHA256>.gz` и манифест.
В нём есть путь, размер и SHA-256 несжатого содержимого каждого файла.
Одинаковые файлы получают одинаковые имена и не зависят от версии приложения.
Ревизия модели и зависимости рабочего процесса закреплены в
`tools/prepare_private_clap.ps1`; CI повторно использует неизменившийся worker.

Манифест встраивается в исполняемый файл при сборке через
`FASTCLOUD_COMPONENT_MANIFEST`. Его доверие обеспечивается подписью обновления
Tauri. Программа не принимает удалённый изменяемый список исполняемых файлов.
HTTPS-загрузка ограничена размерами, gzip распаковывается с ограничением,
контрольная сумма проверяется до активации. Относительные пути проверяются:
переходы вверх, абсолютные пути и имена устройств Windows запрещены.

Хранилище находится в `fastcloud/data/components/clap` внутри данных пользователя.
`blobs` содержит проверенные файлы, `sets/<SHA256>` — полный набор для конкретного
манифеста. На NTFS набор использует жёсткие ссылки на blobs. При отсутствии их
поддержки используются копии. Файлы из установочного каталога всегда копируются,
чтобы следующий установщик не мог изменить их через жёсткую ссылку.
В релизных сборках после успешного переноса удаляются только совпадающие с
проверенным манифестом исходные файлы CLAP. Пользовательские и изменённые файлы
сохраняются. Сборки для разработки не очищают исходные ресурсы проекта.
Набор становится доступным CLAP после полной подготовки. При ошибке частичная
загрузка не запускается, уже проверенные файлы используются при повторе.
После успешной подготовки сохраняются текущий и один предыдущий набор,
устаревшие наборы и файлы без ссылок удаляются из собственного хранилища.

## Релиз

Порядок команд для пользователя не меняется: обновить версию, commit/push,
создать и отправить новый тег. CI сам готовит ресурсы, полный и лёгкий
установщики, оба подписанных манифеста и уведомление сервера.
Релиз сначала собирается как черновик и публикуется после загрузки всех файлов.
Повторный запуск уже опубликованного тега повторяет уведомление, сохраняя файлы.
Старые теги не перемещаются. Обновление backend не требуется.

Локальная проверка без сборки установщиков:

```powershell
python -m unittest discover -s tools -p "test_components.py"
npm --prefix desktop run check
cargo test --manifest-path desktop/src-tauri/Cargo.toml --locked --lib
```
