# Long-collection metadata memory probe

## Scope and reproduction

- Host: Windows 11 Pro, 10.0.26200, x64.
- Base commit: `c8c652b2d9c125e9acd81edb90ac0a74dbe11e70`, dirty Airwave worktree.
- Build: release, opt-level 3, LTO, one codegen unit.
- Window resolution / image-memory profile: not applicable; no UI is started.
- Real `src/api/models.rs::Track`, synthetic metadata, 10,000 unique IDs.
- Each track has a title, artist, genre, description, artwork URL and waveform URL.
- No downloads, audio buffers, decoded artwork, GPU textures or Store are involved.
- The sampler reads the probe process's `WorkingSet64` and `PrivateMemorySize64`
  using a hidden PowerShell process. The sampler's own memory is not included.

```powershell
rtk cargo run -j 1 --release --locked --manifest-path tools/collection-memory/Cargo.toml
rtk cargo test --locked --manifest-path tools/collection-memory/Cargo.toml
rtk cargo clippy --all-targets --locked --manifest-path tools/collection-memory/Cargo.toml -- -D warnings
```

The standalone manifest avoids rebuilding GUI/audio dependencies for a metadata probe.
Its lockfile is included with the probe. Run each repetition in a fresh process.

## Results

Private bytes, in bytes, from three consecutive fresh-process runs:

| Stage | Run 1 | Run 2 | Run 3 |
| --- | ---: | ---: | ---: |
| Baseline after parser/sampler warm-up | 774144 | 716800 | 724992 |
| 10,000 tracks | 13594624 | 13475840 | 13484032 |
| Plus 100 Arc readers | 13594624 | 13475840 | 13484032 |
| Plus one deep collection copy | 25858048 | 25882624 | 25890816 |
| Collections released | 1486848 | 1384448 | 1376256 |

Working set, in bytes:

| Stage | Run 1 | Run 2 | Run 3 |
| --- | ---: | ---: | ---: |
| Baseline | 5484544 | 5009408 | 5013504 |
| 10,000 tracks | 18259968 | 17543168 | 17543168 |
| Plus 100 Arc readers | 18259968 | 17559552 | 17547264 |
| Plus one deep collection copy | 30408704 | 29802496 | 29806592 |
| Collections released | 6332416 | 5623808 | 5574656 |

For this fixture, the collection adds **12.17–12.23 MiB** private bytes;
one deep copy adds another **11.70–11.83 MiB**. Arc readers add no detectable
private-byte increment at this sampling resolution; this does not mean Arc is allocation-free.
Residual memory after drop can be allocator/runtime retention and is not proof of a leak.
These are process counters, not exact live-heap allocation totals.

## Change prompted by the probe

`likes_grid` and `track_rows` previously constructed `Arc::new(tracks.to_vec())`
on every draw. Both now borrow the incoming slice and create an owned queue only
when playback is requested. `track_rows` also no longer clones every row before
drawing it; multi-selection uses the existing display-ordered selection helper.

This removes identifiable copies from those functions. The numbers above illustrate
the cost of a copy; they are **not** an end-to-end before/after application measurement.
Filtering, selection snapshots and other layers can still allocate.

## Still required

- Full-app cold/warm measurements with artwork and audio enabled.
- Feed first-pass rendering, playlist posts and scroll-position visual checks.
- A 500-item scroll scenario, repeated detail navigation and long playback.
- End-to-end frame-time and memory comparison before changing image-cache budgets.

No image-memory budget was reduced based on this isolated probe.
