# Performance pass: desktop and catalogue

## Changes

- The desktop no longer refreshes an inactive library snapshot in a loop. An active request still refreshes stale data.
- Artwork and waveform downloads reuse connections, limit response size and concurrent artwork downloads, and avoid an extra artwork byte copy before writing the disk cache. Unmounted artwork queries now leave memory after 15 seconds.
- Queue insertion moves the tail instead of cloning every track. The desktop player poll sends the queue only when its revision changes, and Discord presence updates only on a state change, seek, or periodic synchronization.
- Catalogue responses share cached track and playlist vectors through `Arc` until serialization. Single-item lookups no longer clone an entire collection.
- Long track and playlist lists and their grids mount only visible rows plus overscan. They retain the complete scroll height and original playback/selection indices. The search keyboard cursor scrolls to its item.

## Browser measurement

A temporary Vite page rendered 5,000 synthetic tracks in headless Chrome with a 700 px scroll area and the browser's default window size. Measurements below are one run after scrolling halfway. The baseline used the same components with virtualization disabled. `usedJSHeapSize` is a browser estimate, not application working set.

| View | Mounted items before → after | DOM nodes before → after | JS heap before → after | Scroll height |
| --- | ---: | ---: | ---: | ---: |
| Track rows | 5,000 → 27 | 110,012 → 608 | 144.5 MB → 14.9 MB | 340,095 px in both |
| Library grid | 5,000 → 57 | 35,012 → 413 | 77.4 MB → 14.0 MB | 473,793 px in both |

The same 5,000-item comparison with an 800 × 900 browser window retained the exact scroll height in both views. A keyboard cursor at index 3,000 remained mounted and scrolled into view. These measurements isolate list rendering. They do not measure the installed Tauri process, real artwork decoding, audio buffers, or network latency.

A second synthetic scroll check with 5,000 playlists kept 57 grid cards or 27 list items mounted halfway through the collection. Both views displayed items near index 2,500 after the scroll and retained their original scroll height.

## Verification

- Desktop TypeScript and production Vite build.
- Tauri library tests and Rust workspace check.
- Synthetic browser scroll and keyboard-cursor checks described above.

The desktop bundle still triggers Vite's 500 kB chunk warning. Splitting the app into route chunks may improve initial load, but requires a separate cold-start measurement to justify the extra requests and loading states.
