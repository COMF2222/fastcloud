# Desktop memory work — 0.4.20

Changes are limited to the desktop client. No server changes or user data
migrations are required. Sound quality, artwork resolution, wallpapers, panel
blur, radio features and the CLAP model weights are unchanged.

## Measurements

Windows x64, production NumPy/ONNX Runtime libraries from the existing CLAP
build environment, identical local quantized models. The isolated probe runs
eight text prompts, then six ten-second synthetic audio requests. It includes
the Windows venv launcher and descendant interpreter processes. No account,
network or real audio recording is used. Counters are retained process private
bytes and summed working sets, not whole-application or GPU memory.

| After the sixth audio request | Before | After |
| --- | ---: | ---: |
| Private memory | 433.21 MiB | 367.74 MiB |
| Working set | 380.24 MiB | 334.58 MiB |

Private memory fell 65.47 MiB (15.11%) in this run. Five warm audio requests
took 0.202–0.214 seconds before and 0.190–0.237 seconds after. Maximum vector
difference across all eight text and six audio results was **0.0**.

The worker now loads each model only when needed, disables the CPU tensor arena
that retained inference peaks, and drops request-sized arrays before waiting on
stdin. Ready time fell from 6.26 to 0.57 seconds, but the first audio request now
includes loading its model (5.09 seconds in this run). Native audio analysis
already runs in a background blocking task after 35 seconds of playback; this
does not delay Play. Weights remain loaded for subsequent requests and the
existing 180-second idle worker release is retained.

Reproduce against an unmodified source copy with the same Python/model paths:

```powershell
python tools/profile_clap_memory.py --python <venv-python.exe> --model <model-directory> --before <old-clap_worker.py> --after desktop/clap_worker.py
```

The probe enforces read timeouts and compares every vector; it does not report
the small venv launcher as if it were the inference process. Full-app savings
depend on listening, cache contents and the WebView and have not been measured
as an installed before/after application pair.

## Artwork and rendering

The artwork bridge now returns a path to the verified cached image rather than
an image-sized base64 string. WebView uses Tauri's asset protocol, scoped to the
generated artwork directory only. Cache hits inspect a twelve-byte signature
without reading/base64-encoding the full image in Rust. The original bytes and
CDN size selection are preserved. The existing 128 MiB disk quota remains.
If writing fails, the bounded data-URL fallback still displays the image. A
view resolves an evicted file once rather than retaining an unusable URL or
retrying indefinitely. Concurrent writes use distinct partial files.

A 1 MiB fixture returns a path shorter than 512 characters rather than roughly
1.33 MiB of base64, while the on-disk bytes remain identical. This describes IPC
payload savings, not a measured reduction of decoded image/GPU memory.

The Full profile's animated `.main::after` glow/dot layer and its keyframes were
removed. Other profile effects remain. In the built browser preview at
1280×720, Full mode reports pseudo-element `content: none` and
`animation-name: none`, while the track list retains `backdrop-filter: blur(14px)`.
This browser check does not test the native asset protocol or real audio.
